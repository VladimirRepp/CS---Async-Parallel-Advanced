# Проект Sample_2 — Рефакторинг через Sprout Method

## Назначение

Учебный проект, демонстрирующий приём **Sprout Method** (проращивание метода) при работе с legacy-кодом. Показывает, как добавить новый функционал, не изменяя существующий проверенный метод.

## Структура проекта

| Файл | Назначение |
|------|-----------|
| `PriceCalculator.cs` | Класс с legacy-методом `CalculatePrice` и новым «проросшим» `CalculatePriceWithDiscount` |
| `Program.cs` | Демонстрация: расчёт цены без скидки и со скидкой |

Пространство имён: `Sample_2.Legacy`.

## Что делает код

`PriceCalculator` рассчитывает стоимость партии товара:

1. `CalculatePrice(quantity, unitPrice)` — legacy-метод: базовая цена как `quantity * unitPrice`. **Не изменяется.**
2. `CalculatePriceWithDiscount(quantity, unitPrice)` — новый метод:
   - вызывает legacy-метод для получения базовой цены;
   - применяет скидку через `ApplyDiscount`.
3. `ApplyDiscount(basePrice)` — изолированное правило: при `basePrice > 1000` возвращает `basePrice * 0.90m` (скидка 10%), иначе — без изменений.

Демонстрация в `Program.cs`: `quantity = 10`, `unitPrice = 500`. База = 5000, что больше 1000, поэтому со скидкой получается 4500.

## Зачем используется Sprout Method

Legacy-метод `CalculatePrice`:

- уже работает в продакшене и покрыт тестами;
- может иметь скрытые зависимости и неочевидные побочные эффекты;
- его изменение несёт риск регрессии.

Sprout Method позволяет добавить функционал **рядом**, а не **внутри** старого кода:

- старый метод остаётся нетронутым — риск регрессии минимален;
- новая логика вызывается из нового метода, который использует старый как строительный блок;
- новую логику можно тестировать независимо;
- при необходимости новый метод легко удалить или переписать без отката legacy-кода.

## Полезная теория

**Sprout Method** (М. Фаулер, «Рефакторинг») — техника добавления поведения в систему путём создания нового метода, который вызывается из существующего кода, при этом сам существующий код минимально затрагивается (в идеале — одной строкой-вызовом).

**Sprout Class** — вариант приёма: новая функциональность выносится в отдельный класс, а legacy-код лишь делегирует ему.

**Когда применять:**

- код сложно понять или протестировать;
- изменение существующего метода рискованно;
- добавляемая логика логически отделима от текущей ответственности метода.

**Когда не применять:**

- если старый метод тривиален и полностью покрыт тестами — проще отрефакторить его напрямую;
- если «прорастание» приводит к дублированию или размытию ответственности класса.

**Связанные приёмы:**

- **Wrap Method** — переименовать старый метод и создать обёртку с прежним именем, вызывающую новую логику до/после.
- **Extract Method** — вынести фрагмент существующего метода (в отличие от Sprout, изменяет старый код).
- **Branch by Abstraction** — введение абстракции для постепенной замены реализации.

**Признаки качественного результата:**

- legacy-метод не изменён (в коде — маркер `#region === Legacy ===` и комментарий «не изменять»);
- новый метод читается как композиция: получить базу → применить правило;
- бизнес-правило (порог, процент) локализовано в отдельном методе;
- новая логика не дублирует расчёт базы, а переиспользует его.

## Замечания по текущей реализации (для дальнейшего улучшения)

- Магические числа `1000` и `0.90m` не вынесены в именованные константы (`DiscountThreshold`, `DiscountRate`).
- Порог и процент уместно вынести в параметры или конфигурацию — иначе правило зашито в класс.
- Для денежных величин желательно явно фиксировать правила округления (`Math.Round` с `MidpointRounding`), иначе накопление дробных значений может дать неожиданный результат.
- `CalculatePriceWithDiscount` и `ApplyDiscount` размещены в том же классе, что и legacy-метод; для строгого следования Sprout Method можно было вынести их в отдельный класс (`DiscountedPriceCalculator`), оставив legacy-класс нетронутым.
- Проверка `basePrice > 1000` — строгая; стоит явно оговорить в комментарии поведение на границе (ровно 1000 — без скидки).

## Сборка и запуск

Требуется .NET SDK с поддержкой C# (top-level statements в `Program.cs`).

```
dotnet run
```

Ожидаемый вывод:

```
Чек без скидки (legacy code):
 Количество (10), Цена за шт (500) = 5000

Чек со скидкой (modified code):
 Количество (10), Цена за шт (500) = 4500,0
```
